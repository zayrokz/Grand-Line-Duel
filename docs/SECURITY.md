# Revue de sécurité — Grand Line Duel

Modèle : un adversaire contrôle entièrement son navigateur (il peut lire tout ce que son client
reçoit, modifier le JavaScript, appeler directement les API Firebase avec son jeton). Le serveur
(Cloud Functions + règles Firestore) est la seule source de vérité.

## Menaces et parades

| #   | Menace                                                                             | Parade mise en place                                                                                                                                                                                                                                                                     | Vérification                                                        |

| 1   | Écrire directement dans Firestore (état de partie, statistiques, profil, victoire) | Règles **deny by default** : aucune écriture client sur aucun chemin. | 2   | Jouer un coup illégal ou forgé                                                     | `submitMove` : schéma Zod strict du coup, puis `validateMove` du moteur (mêmes règles que le client) **dans une transaction** avec l'état secret. | 3   | Jouer à la place de l'adversaire / hors de son tour                                | Le siège est déduit de l'`uid` authentifié côté serveur (jamais envoyé par le client) ; vérification de l'appartenance (`playerUids`) et du joueur actif.                                                                                                                                | `not-a-player`, `not-your-turn` testés                              |

## Risques résiduels assumés

- **Réservation depuis la pyramide** : la carte était visible avant d'être réservée ; un client
  attentif peut la déduire en comparant la pyramide avant/après (comme autour d'une vraie table).
  Le serveur ne la publie jamais explicitement.
- **Composition du sac** : déductible (25 jetons − plateau − jetons des joueurs, tous publics), comme
  dans le jeu physique. Seul l'ordre de tirage est secret.
- **`style-src 'unsafe-inline'`** : conservé pour les widgets Google (reCAPTCHA, Auth). Le code de
  l'application fonctionne sans (testé) : vous pouvez le retirer après vérification en production.
- **App Check sur Firestore** : l'application est **manuelle** dans la console Firebase (voir README).
  Tant qu'elle n'est pas activée, les lectures Firestore restent protégées par les règles mais pas
  par l'attestation.
- **Limitation par utilisateur** : un attaquant pourrait multiplier les comptes anonymes ; App Check
  et les quotas d'Identity Platform en limitent le coût. Activez la suppression automatique des
  comptes anonymes inactifs (Identity Platform) si nécessaire.
- **Dépendances** : `npm audit` signale des avis transitifs dans le SDK `firebase` (`@grpc/grpc-js`,
  utilisé seulement par la version Node du client Firestore, pas par le bundle navigateur) et `uuid`
  (via `gaxios`, API concernée non utilisée). Aucun correctif non cassant n'existe à ce jour ;
  à surveiller avec Dependabot.

## Ce qui est public / ce qui ne l'est pas

| Public par nature (peut être commité ou exposé)              | Secret (jamais dans le dépôt)                                             |
| ------------------------------------------------------------ | ------------------------------------------------------------------------- |
| Configuration web Firebase (`apiKey`, `projectId`, `appId`…) | Clé JSON du compte de service de déploiement (`FIREBASE_SERVICE_ACCOUNT`) |
| Clé de site reCAPTCHA Enterprise                             | Jetons de débogage App Check (à révoquer après usage)                     |
| Région des Functions, règles Firestore, index                | Graines et états secrets des parties (`gameSecrets`, côté serveur)        |
| `ALLOWED_ORIGINS`                                            | Mots de passe des comptes (gérés par Firebase Auth)                       |
